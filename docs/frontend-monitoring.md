# Мониторинг ошибок frontend

Frontend отправляет ошибки в облачный GlitchTip через SDK `@sentry/nextjs`.

Организация: `robot-warehouse`.
Проект: `robot-warehouse-frontend`.
Адрес сервиса: https://app.glitchtip.com

Текущая интеграция проверена с `@sentry/nextjs` 11.11.0,
Next.js 16.4.5 и Turbopack.

## Что подключено

- Ручная отправка исключений из браузера.
- Сбор необработанных браузерных ошибок.
- Отправка ошибок React-рендера через `error.tsx` и `global-error.tsx`.
- Сбор серверных ошибок Next.js через `onRequestError`.
- Загрузка source maps при production-сборке с токеном.

NestJS и Edge runtime этой интеграцией не охвачены.

Session Replay и sampling транзакций производительности не настроены.

## Как это работает

Мониторинг состоит из двух независимых процессов.

### Отправка ошибок во время работы приложения

Приложение использует DSN, чтобы отправлять события в frontend-проект GlitchTip.

Браузерный SDK запускается до гидратации React.
Серверный SDK инициализируется при запуске экземпляра сервера Next.js.

Ошибки, перехваченные нашими React error boundaries,
отправляются явно через `Sentry.captureException`.

### Загрузка source maps во время сборки

Production JavaScript преобразован и минифицирован.
Source maps позволяют сопоставить ошибку с исходным TypeScript/TSX-кодом.

`withSentryConfig` подключает обработку сборки и загрузку карт в GlitchTip.
Для загрузки нужен отдельный API-токен.

DSN не заменяет API-токен:

- DSN нужен приложению для отправки событий;
- API-токен нужен процессу сборки для загрузки артефактов.

Приложение может отправлять ошибки без токена сборки.
Однако для читаемого stack trace нового production-бандла
должны быть доступны соответствующие source maps.

## Назначение файлов

| Файл                                     | Ответственность                                              |
| ---------------------------------------- | ------------------------------------------------------------ |
| `frontend/src/instrumentation-client.ts` | Инициализация браузерного SDK и hook навигации               |
| `frontend/src/instrumentation.ts`        | Серверная точка входа Next.js: `register` и `onRequestError` |
| `frontend/src/sentry.server.config.ts`   | Настройки SDK для Node.js runtime                            |
| `frontend/src/app/error.tsx`             | Резервный UI и отправка ошибок рендера дочерних сегментов    |
| `frontend/src/app/global-error.tsx`      | Глобальный резервный UI, заменяющий корневой документ        |
| `frontend/next.config.ts`                | Интеграция сборки, release и source maps                     |

`instrumentation.ts` и `instrumentation-client.ts` находятся в `src`,
а не внутри `src/app`.

`error.tsx` и `global-error.tsx` — специальные файлы App Router.
В установленной версии Next.js для повторной попытки используется `retry`.

## Локальная настройка

Команды выполняются из `frontend/`, если не указано другое.

Создайте `.env.local` и задайте:

```dotenv
NEXT_PUBLIC_SENTRY_DSN=<DSN frontend-проекта>
NEXT_PUBLIC_SENTRY_ENVIRONMENT=development
```

Пустой или отсутствующий DSN отключает SDK через `enabled: Boolean(dsn)`.

Для обычной разработки API-токен загрузки source maps не нужен.
Если мониторинг локальных ошибок не требуется, оставьте DSN пустым.

DSN и доступ к проекту можно запросить у ответственного за GlitchTip.

После изменения env-переменных перезапустите dev-сервер.
Для production-браузерного кода потребуется новая сборка:
`NEXT_PUBLIC_*` подставляются при `next build`.

## Переменные окружения

| Переменная                       | Назначение                                                       |
| -------------------------------- | ---------------------------------------------------------------- |
| `NEXT_PUBLIC_SENTRY_DSN`         | Адрес отправки событий                                           |
| `NEXT_PUBLIC_SENTRY_ENVIRONMENT` | Метка окружения, например `development`, `staging`, `production` |
| `SENTRY_AUTH_TOKEN`              | Секретный токен для загрузки артефактов                          |
| `SENTRY_ORG`                     | Slug организации                                                 |
| `SENTRY_PROJECT`                 | Slug проекта                                                     |
| `SENTRY_URL`                     | Базовый URL GlitchTip                                            |

Метка `NEXT_PUBLIC_SENTRY_ENVIRONMENT` не равна режиму сборки:
локальная production-сборка может отправлять события с меткой `development`.

Переменные с префиксом `NEXT_PUBLIC_` доступны браузеру.
Нельзя добавлять этот префикс к API-токену.

## Загрузка source maps

Дополните локальное окружение либо окружение CI:

```dotenv
SENTRY_AUTH_TOKEN=<секретный токен>
SENTRY_ORG=robot-warehouse
SENTRY_PROJECT=robot-warehouse-frontend
SENTRY_URL=[https://app.glitchtip.com](https://app.glitchtip.com)
```

Для проверенной настройки токена используются права:

- Projects → releases (`project:releases`);
- Organization → read (`org:read`).

Полный доступ не требуется.

Выполните:

```bash
pnpm build
```

При наличии токена конфигурация требует также организацию, проект и URL.
Ошибки плагина пробрасываются через `errorHandler`.

После загрузки клиентские source maps удаляются из выходных
артефактов согласно `deleteSourcemapsAfterUpload`.

### Проверка без токена

```bash
SENTRY_AUTH_TOKEN= pnpm build
```

В текущей конфигурации без токена:

- загрузка source maps отключена;
- создание и финализация release отключены;
- сборка должна проходить.

SDK 11.11.0 при этом может выводить:

```text
No auth token provided. Will not create release.
```

В проверенной зависимости проверка токена выполняется до проверки
`release.create`. Поэтому предупреждение возможно даже при `create: false`.
Оно само по себе не означает падение сборки.

## Ручная отправка обработанных ошибок

Если приложение перехватило неожиданную ошибку и обработало её,
при необходимости отправьте её явно:

```ts
import * as Sentry from "@sentry/nextjs";

try {
  await performOperation();
} catch (error) {
  Sentry.captureException(error);
  // Отдельно обновите UI и обработайте неуспешную операцию.
}
```

Не следует отправлять каждую ожидаемую ошибку валидации
как программное исключение.

Не отправляйте одну ошибку вручную в нескольких слоях без необходимости.

## Проверка интеграции

Проверять production-поведение нужно через:

```bash
pnpm build
pnpm start
```

Для проверки отправки можно временно добавить кнопку
с `Sentry.captureException(new Error("Monitoring smoke test"))`.

Для проверки React error boundary ошибка должна возникнуть
во время рендера, а не просто внутри `onClick`.

Временные страницы, кнопки и маршруты с намеренными ошибками
не должны оставаться в итоговом коде.

Для проверки source maps:

1. Соберите приложение с загрузкой карт.
2. Запустите именно эту сборку.
3. Вызовите новую тестовую ошибку.
4. Откройте новое событие в GlitchTip.
5. Проверьте исходный файл, строку и окружающий код.

Сообщение об успешной загрузке карт само по себе недостаточно.

При `cacheComponents: true` тестовый GET-обработчик может выполняться
во время сборки. Для проверки ошибки именно по запросу использовался
`await connection()` перед намеренным `throw`.
Экспорт `runtime = "nodejs"` в этом режиме добавлять не нужно.

## Безопасность и пользовательские данные

`.env.local` не должен отслеживаться Git.

Проверка из корня репозитория:

```bash
git check-ignore -v -- frontend/.env.local
git ls-files -- frontend/.env.local
```

Первая команда должна показать правило игнорирования.
Вторая не должна ничего вывести.

API-токен нельзя публиковать в репозитории, чатах, скриншотах и логах.
При раскрытии токен необходимо отозвать и заменить.

SDK настроен с ограничениями `dataCollection`.
Это не гарантирует отсутствие любых чувствительных данных:
они могут оказаться, например, в тексте ошибки или вручную добавленном контексте.

В проверенном браузерном envelope поле `user.ip_address` отсутствовало,
но присутствовало в сохранённом GlitchTip событии.
Полное удаление IP на стороне сервиса не подтверждено.

При настройке дополнительных контекстов повторно проверяйте
фактическое содержимое отправляемых событий.

## Что нужно для CI и деплоя

Автоматическая загрузка в CI пока не подключена этой задачей.

Ответственному за сборку необходимо:

- передать `SENTRY_AUTH_TOKEN` через секреты CI;
- задать `SENTRY_ORG`, `SENTRY_PROJECT`, `SENTRY_URL`;
- передать публичные DSN и метку окружения до `next build`;
- проверить загрузку карт и новое событие на стенде;
- использовать на стенде артефакты той сборки, для которой загружены карты.

API-токен нужен сборке, а не браузеру.

## Проведённые локальные проверки

В рамках настройки вручную проверены:

- отправка обработанной браузерной ошибки;
- сбор необработанной ошибки обработчика клика;
- отправка ошибки React-рендера через `error.tsx`;
- работа `global-error.tsx` при отсутствии ближайшего `error.tsx`;
- серверная ошибка Next.js Route Handler;
- загрузка source maps и восстановление исходного TSX;
- сборка без токена;
- чистая сборка после удаления тестовых маршрутов.

Это ручные проверки, а не автоматизированные тесты.

Ошибку непосредственно корневого layout отдельно не воспроизводили.
Работа на развёрнутом стенде и автоматизация CI ещё не проверены.
