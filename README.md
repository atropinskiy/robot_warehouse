# Robot Warehouse

Платформа управления роботами на симулируемом складе: пользователь собирает карту склада, добавляет роботов, создаёт задания на перевозку грузов и наблюдает за их выполнением в real time.

## Инструменты разработки

Менеджер пакетов — **pnpm** (и для frontend, и для backend).

### Frontend

- **Next.js**, TypeScript
- **TanStack Query** — серверное состояние
- **Zustand** — клиентское состояние
- **shadcn/ui** + **Tailwind** — UI kit
- **React Hook Form** + **Zod** — формы и валидация
- **Socket.IO** — realtime
- **Feature-Sliced Design** — архитектура
- **ESLint**, **Prettier**, **Husky**
- **Vitest** + **React Testing Library** — тесты
- **Storybook** — библиотека UI-компонентов
- **Sentry / GlitchTip** — логирование ошибок

### Backend

- **NestJS**, TypeScript
- **Socket.IO** — realtime
- **PostgreSQL** + **Prisma / TypeORM**
- **Redis**, **BullMQ** — очереди и фоновые задачи
- **Swagger** — документация API
- **OpenAI** — ИИ-помощник (задания из текста, сводки)
- **ESLint**, **Prettier**, **Husky**
- **Docker** — локальная разработка и прод

### Инфраструктура (прод)

- **Grafana** + **Loki** + **Promtail** — логирование
- **Prometheus** + **node_exporter** + **cAdvisor** — метрики
- **Nginx**
- CI/CD — **GitHub Actions** (линтеры, тесты, билд, typecheck на каждый PR)

### Рабочий процесс

- Таск-менеджер — **GitHub Projects**.
- Trunk-based подход с пулл-реквестами.
- Прямой пуш в основную ветку запрещён — только PR с код-ревью.
- Переменные окружения: `.env` локально, секреты GitHub для CI/CD (в репозиторий не коммитим).
- Логирование и сбор метрик в проде обязательны.

## Правила работы с GitHub

* Main ветка для прода, пока не трогаем.
* При разработке фичи сначала создаем себе ветку на основе dev. Пример названия: Номер таски_Кратко_Автор 33_autorization_alextr

### Порядок создания пул реквеста:

1. Перед пул реквестом переключаемся локально на ветку dev, пулим изменения из репозитория, чтобы dev была актуальной.
2. Заходим на свою ветку и делаем merge с dev.
3. Если конфлиектов нет, делаем пул реквест на dev.

### Порадок проведения ревью.

1. Ваши замечания нужно разделить на 2 вида: Критичные и Рекомендации.
   Критичные замечания необходимо исправить. Рекомендации можно не исправлять в пользу скорости разработки.
